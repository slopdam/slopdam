# slopdam 상세 설계 (v0.2 설계안)

> 근거 자료는 [RESEARCH.md](RESEARCH.md), 규칙 전체 목록은 [RULES.md](RULES.md).

## 0. 한 줄 요약

AI가 만든 문자열에서 `ㅡ` `—` 같은 대시류, 이모지, 구분선, 마크다운 흔적을 걷어냅니다. 결과는 **누가 읽는가**에 따라 두 가지로 나뉩니다.

- **`reader`(기본)**: 일반 사용자가 읽기 편한 담백한 한국어 문장
- **`dev`**: 개발자가 보고 검색하기 편한, 정보 손실 없는 기계 친화 형태

```
입력 : ✅ **저장 완료** ㅡ 2024–2025년 데이터 3건 처리했습니다! 🎉

reader: 저장 완료: 2024~2025년 데이터 3건 처리했습니다.
dev   : [OK] 저장 완료 - 2024-2025년 데이터 3건 처리했습니다!
```

---

## 1. 목표와 대상

| | 1. `reader` (기본) | 2. `dev` |
|---|---|---|
| 읽는 사람 | 서비스 사용자, 운영/기획 담당자, CLI 사용자 | 개발자, 로그 수집기(ELK, Loki, CloudWatch) |
| 우선순위 | 자연스러운 한국어, 차분한 어조, 군더더기 없음 | 정보 보존, grep/파싱 가능, ASCII 친화, 일관된 토큰 |
| 이모지 | 삭제 | 의미 있는 상태 이모지는 `[OK]` `[FAIL]` `[WARN]` 태그로 보존, 나머지 삭제 |
| 대시 `ㅡ` `—` (문장 안) | 콜론 `: ` (앞말을 받아 뒤에서 설명) | ` - ` |
| 숫자 범위 `2024–2025` | `2024~2025` (한국어 범위 표기 관례) | `2024-2025` |
| 감탄부호 `완료!` | `완료.` | 유지 |
| 군더더기 표현 `성공적으로` | `strong` 레벨에서 삭제 | 유지 |
| 인라인 코드 `` `a.yaml` `` | 백틱 제거, 내용 유지 | 백틱 유지 |

**설계 원칙**: 두 프로필은 **같은 탐지 엔진**을 씁니다. 다른 것은 "탐지된 패턴을 무엇으로 바꾸는가(액션)"뿐입니다. 그래서 린터 결과와 포맷터 결과가 일치하고, 프로필을 추가해도 탐지 로직은 그대로입니다.

## 2. 분류 기준: 어떤 출력에 어떤 프로필을 쓰는가

판단 기준은 하나입니다. **"이 문자열을 최종적으로 사람이 화면에서 읽는가, 도구나 개발자가 다루는가?"**

| 출력 대상 | 프로필 | 이유 |
|---|---|---|
| CLI 표준출력 메시지, 진행 상황 안내 | `reader` | 사용자가 터미널에서 읽음 |
| 알림(슬랙, 이메일, 푸시), 리포트 요약 | `reader` | 비개발자도 읽음 |
| 화면에 노출되는 오류 문구 | `reader` | 사용자 대면 문구 |
| 로그 파일, 로그 수집기 | `dev` | 검색, 파싱, 집계 대상 |
| DEBUG 레벨 로그 | `dev` | 개발자 전용 |
| 커밋 메시지, 코드 주석 (린터) | `dev` | 개발자가 읽고 도구가 처리 |

### 라우팅 예: 로거 하나, 핸들러 둘

```python
console = logging.StreamHandler()                    # 사람이 보는 화면
console.setFormatter(PlainFormatter("%(message)s"))  # profile="reader" 가 기본

file = logging.FileHandler("app.log")                # 개발자/수집기
file.setFormatter(PlainFormatter("%(asctime)s %(levelname)s %(name)s %(message)s", profile="dev"))
```

### `profile="auto"` (v0.3)

명시하지 않아도 분류되도록 하는 선택 기능입니다.

1. 핸들러 종류: `StreamHandler`(tty) → `reader`, `FileHandler` 및 네트워크 핸들러 → `dev`
2. 레벨: `DEBUG` → 항상 `dev`
3. 환경 변수 `PLAINLOG_PROFILE` 이 있으면 우선 적용

## 3. 처리 파이프라인

모든 단계는 결정적(정규식과 문자표만 사용)이고, 순서가 고정되어 있습니다.

```
입력 문자열
  │
  ├─ S0 빠른 경로      ASCII만 있으면 S1~S4 생략 (S5, S6만 실행)
  ├─ S1 보호 구역 분리   URL, 인라인 코드, key=value 의 값, 파일 경로는 마스킹
  ├─ S2 문자 정규화     보이지 않는 문자 제거, NBSP 변환, 전각→반각, 둥근 따옴표→직선
  ├─ S3 대시 계열       ㅡ, —, ─ 등 25종을 "런" 단위로 묶어 문맥 판정 (4장)
  ├─ S4 이모지         Extended_Pictographic 기반 탐지, 프로필별로 삭제/태그 (5장)
  ├─ S5 마크다운/구분선  **굵게**, ### 제목, ---, ===== 등
  ├─ S6 어조           한글 뒤 !, 군더더기 표현 (프로필/레벨에 따라)
  ├─ S7 보호 구역 복원
  └─ S8 공백 정리       연속 공백 축약, 앞뒤 공백 제거, 빈 줄 제거
결과 (빈 문자열이면 Filter가 레코드를 버림)
```

**불변식(테스트로 보장)**

- 멱등성: `clean(clean(x)) == clean(x)`
- 보호 구역 보존: URL, 백틱 안 내용, `key=value` 의 값은 바이트 단위로 같음
- 트레이스백 불변: 예외 스택 문자열은 처리 대상이 아님
- ASCII 안정성: 대상 패턴이 없는 ASCII 문자열은 그대로 통과

## 4. 대시 계열 설계 (`ㅡ` 포함)

### 4.1 문자군

한국 사용자는 두벌식 자판에서 `m` 키로 `ㅡ`를 쳐서 줄표(—) 대신 씁니다. AI 모델은 `—`를 많이 씁니다. 둘 다, 그리고 비슷하게 생긴 문자 전부를 하나의 계열로 다룹니다.

| 군 | 문자 (코드포인트) | 기본 판정 |
|---|---|---|
| **H. 하이픈류** | `‐` 2010, `‑` 2011, `−` 2212, `﹣` FE63, `－` FF0D | 항상 `-` (의미가 하이픈이므로 문맥 판정 없음) |
| **D. 줄표류** | `‒` 2012, `–` 2013, `—` 2014, `―` 2015, `⸺` 2E3A, `⸻` 2E3B, `﹘` FE58, `︱` FE31, `︲` FE32, `⹀` 2E40 | 문맥 판정 (4.2) |
| **E. 한글 ㅡ류** | `ㅡ` 3161 (호환 자모), `ￚ` FFDA (반각), `ᅳ` 1173 (조합형 중성, **초성 뒤가 아닐 때만**) | 문맥 판정 (4.2) |
| **L. 선 문자류** | `─` 2500, `━` 2501, `┄`~`┋` 2504-250B, `╌`~`╏` 254C-254F, `═` 2550, `⎯` 23AF, `⏤` 23E4, `➖` 2796 | 문맥 판정 (4.2) |
| **C. CJK 닮은꼴** | `一` 4E00, `ー` 30FC, `ｰ` FF70 | **3개 이상 연속일 때만** 구분선으로 삭제 (한자/가나 본문 보호) |
| **W. 물결류** | `〜` 301C, `～` FF5E | `~` |
| **A. ASCII 반복** | `=` `-` `*` `#` `~` `_` `+` 5개 이상 연속 | 구분선으로 삭제 |

> `ㅡ`를 NFKC 정규화하면 사라지지 않고 `ᅳ`(U+1173)로 바뀝니다. 그래서 정규화만으로는 해결되지 않고, E군에 세 코드포인트를 모두 넣어야 합니다. 조합형 `ᅳ`는 초성(U+1100-115F, A960-A97C) 바로 뒤에 오면 음절의 일부이므로 건드리지 않습니다.

### 4.2 문맥 판정표

D, E, L군 문자가 연속된 덩어리(런)를 하나의 단위로 보고, 앞뒤 문자로 판정합니다.

| # | 상황 | 예 | `reader` | `dev` |
|---|---|---|---|---|
| 1 | 런 길이 2 이상 | `ㅡㅡ`, `ㅡㅡㅡ`, `──`, `——` | 삭제 | 삭제 |
| 2 | 숫자 사이 | `2024–2025`, `3ㅡ5` | `~` | `-` |
| 3 | 줄 맨 앞 + 뒤에 공백 (목록 기호) | `ㅡ 항목` | `- ` | `- ` |
| 4 | 앞뒤가 공백 | `완료 ㅡ 다음` | `: ` | ` - ` |
| 5 | 앞뒤가 글자 (붙여 씀) | `완료—다음` | `: ` | ` - ` |
| 6 | 한쪽만 공백, 한쪽은 글자 | `완료 —다음` | `: ` | ` - ` |
| 7 | 줄 끝, 문장부호 옆, 따옴표 안 단독 | `완료 —`, `"—"` | 삭제 | 삭제 |

- 4~6번에서 `reader`가 콜론을 쓰는 이유: AI 문장에서 줄표는 주로 "앞말 — 그에 대한 설명/결과" 구조로 쓰입니다 (`저장 완료 — 3건 처리`). 콜론은 이 관계를 그대로 유지하면서 일반 키보드로 입력할 수 있는 기호입니다. 설정 `dash.inline = "colon" | "comma" | "hyphen" | "space"` 로 바꿀 수 있습니다.
- 4~6번 뒤에 이미 쉼표나 마침표가 있으면 중복 문장부호를 만들지 않습니다 (`완료 ㅡ, 다음` → `완료, 다음`).
- 2번 `reader`의 `~`는 국립국어원 문장 부호 규정의 물결표 용법(기간, 범위)을 따릅니다.

### 4.3 오탐 방지 목록 (반드시 그대로 남아야 함)

`2026-11-21`, `--dry-run`, `a -- b`, `x-y`, `UTF-8`, `一般`, `コーヒー`, `ㅋㅋ`, `-1`, `k8s-node-01`

## 5. 이모지 설계

### 5.1 탐지

- 기준: Unicode `Extended_Pictographic` 속성 + 수식 문자(피부색 1F3FB-1F3FF, ZWJ 200D, VS16 FE0F, 키캡 20E3, 국기 지역 표시자 1F1E6-1F1FF, 태그 E0020-E007F)
- 구현: 서드파티 `regex` 모듈이 있으면 `\p{Extended_Pictographic}` 사용, 없으면 `emoji-data.txt`에서 생성한 범위표 사용 (빌드 스크립트 `scripts/gen_emoji.py`, Unicode 버전 고정)
- 그래핌 단위 처리: `👨‍👩‍👧`, `🇰🇷`, `1️⃣` 는 하나의 덩어리로 처리 (`1️⃣` → `1`)
- **제외**: `©` `®` `™` (Extended_Pictographic 이지만 법적 표기), `※` (한국어 참고 표시), `°` `℃`

### 5.2 프로필별 액션

| 이모지 | 의미 | `reader` | `dev` |
|---|---|---|---|
| ✅ ✔️ ☑️ 🟢 | 성공 | 삭제 | `[OK]` |
| ❌ ✖️ 🔴 ⛔ | 실패 | 삭제 | `[FAIL]` |
| ⚠️ 🟡 | 경고 | 삭제 | `[WARN]` |
| ℹ️ 💡 | 정보 | 삭제 | 삭제 |
| 🚀 🎉 ✨ 🔥 💪 👉 📦 등 | 장식 | 삭제 | 삭제 |

- `dev` 태그는 메시지 맨 앞에 있을 때만 태그로 바꾸고, 문장 중간이면 삭제합니다 (`저장 ✅ 완료` → `저장 완료`).
- 로그 레벨과 중복되면 태그를 생략합니다 (`ERROR` 레코드의 `❌` → 삭제). 포맷터가 레코드 레벨을 알기 때문에 가능합니다.

## 7. 보호 구역

다음 범위는 S1에서 마스킹하고 S7에서 그대로 복원합니다.

| 보호 대상 | 패턴 | 예 |
|---|---|---|
| URL | `https?://\S+` | `https://a.com/x—y` |
| 인라인 코드 내용 | `` `...` `` | `` `a—b` `` (reader 는 백틱만 제거) |
| key=value 의 값 | `\b\w+=("[^"]*"|\S+)` | `title="—"` |
| 파일 경로 | `(/|\./|~/)\S+`, `[A-Z]:\\\S+` | `/tmp/a—b.txt` |

## 8. 레벨 (프로필과 별개의 축)

프로필은 **무엇으로 바꾸는가**, 레벨은 **얼마나 적극적으로 바꾸는가**를 정합니다.

| 레벨 | 내용 |
|---|---|
| `basic` (기본) | 3~6장의 문자/형식 규칙 전부. `ㅡ` 포함 대시 계열 전부 처리 |
| `strong` | basic + `tone.filler` 삭제 (reader), 중복 문장부호 정리 |
| `strict` | strong + 한글/라틴/숫자/ASCII 이외 모든 기호를 린터에서 경고 (런타임은 변경 안 함) |

조합: `PlainFormatter(profile="reader", level="basic")` 이 기본값입니다.

## 9. 규칙 ID 체계와 정의 포맷

- ID: `<군>.<이름>` (예: `dash.eu`, `dash.em`, `emoji.status`, `md.emphasis`)
- 비활성화나 무시는 접두어 단위로 가능: `disable = ["emoji"]` 는 `emoji.*` 전체

언어 공통 규칙은 YAML로 정의하고, 각 언어 패키지가 빌드 시 코드를 생성합니다 (v0.3, Python 프로토타입은 코드에 직접 정의).

```yaml
# rules/dash.yaml
- id: dash.eu
  level: basic
  chars: ["ㅡ", "ￚ", "ᅳ"]
  context: dash-run          # 4.2 판정표 사용
  actions:
    reader: { inline: ": ", range: "~", bullet: "- ", run: "" }
    dev:    { inline: " - ", range: "-", bullet: "- ", run: "" }
  tests:
    detect:   ["완료 ㅡ 다음", "ㅡㅡㅡㅡ", "ㅡ 항목"]
    preserve: ["그", "ㅋㅋ", "의"]
    expect:
      reader: { "완료 ㅡ 다음": "완료: 다음" }
      dev:    { "완료 ㅡ 다음": "완료 - 다음" }
```

## 10. 설정 파일 (`slopdam.toml` 또는 `pyproject.toml [tool.slopdam]`)

```toml
profile = "reader"         # reader | dev | auto
level = "basic"            # basic | strong | strict
disable = ["md.code"]      # 규칙 ID 또는 접두어
allow-chars = ["→"]        # 이 문자는 건드리지 않음

[dash]
inline = "colon"           # colon | comma | hyphen | space  (reader 전용)
range = "tilde"            # tilde | hyphen

[emoji]
status-tags = true         # dev: ✅→[OK]
tags = { "🐛" = "[BUG]" }  # 사용자 정의 태그

[lint]
scope = "log-calls"        # log-calls | strings | all
include = ["src/**"]
exclude = ["tests/fixtures/**"]
```

| Java Logback | `%plainmsg` Converter, Log4j2 `RewritePolicy` | v0.4 |
| Go `log/slog` | `slopdam.NewHandler(inner, opts)` | v0.4 |

공통 규칙: 원본 레코드 불변(포맷터), 예외 스택 불변, 구조화 필드는 문자열 값만 처리(`fields = "strings" | "message-only"`).

## 12. 린터와 자동 수정

### 탐지 범위 (`lint.scope`)

| 값 | 의미 | 구현 |
|---|---|---|
| `log-calls` (기본) | 로그/print 호출의 문자열 인자만 | Python: `ast` 호출 노드 + 문자열/f-string 상수. 그 외 언어: 줄 단위 휴리스틱(v0.2) 후 tree-sitter(v0.3) |
| `strings` | 모든 문자열 리터럴 | 위와 동일, 호출 조건 없이 |
| `all` | 주석과 독스트링 포함 모든 줄 | 줄 단위 |

### 출력

- `text` (기본): `path:line:col: dash.run 'ㅡ' -> ': '` (reader 기준 수정안까지 표시)
- `json`, `sarif` (GitHub code scanning), `github` (Actions annotation)
- 종료 코드: 0 깨끗함, 1 발견, 2 설정 오류

### `slopdam fix` (v0.2)

- AST로 문자열 리터럴 위치를 정확히 잡고, **리터럴 내용만** 치환합니다 (따옴표 종류, 접두어 `f` `r` `b`, 이스케이프 보존).
- 소스에 `"—"` 처럼 이스케이프로 쓴 경우도 해석 후 탐지하고, 수정은 이스케이프를 지우는 방식으로 합니다.
- f-string의 `{...}` 표현식 부분은 건드리지 않습니다.
- 기본은 바로 고치고 바꾼 위치를 출력합니다. `--diff` 는 파일을 쓰지 않고 바뀔 내용만 보여 주며, 바뀔 것이 있으면 exit 1 (CI용).
- 서식 자리(`%s`, `{0}`)와 f-string 표현식은 판정할 때 글자 하나로 취급합니다. 그래야 `완료 ㅡ %s건` 의 대시가 문장 안 대시로 판정됩니다.
- 고친 결과가 원래 문자열 앞뒤에 없던 공백을 만들면 지웁니다.

### 무시 주석

- `# slopdam: ignore` 줄 전체 무시
- `# slopdam: ignore[dash,emoji.status]` 해당 규칙만 무시
- 파일 단위: 첫 10줄 안의 `# slopdam: ignore-file`

## 13. 성능 목표

| 항목 | 목표 | 방법 |
|---|---|---|
| ASCII 메시지 (대상 없음) | 메시지당 1µs 이하 오버헤드 | `str.isascii()` 빠른 경로 + ASCII 규칙만 결합 정규식 1회 |

| 린터 | 10만 줄 2초 이하 | 파일 단위 병렬, 트리거 문자 없는 파일 건너뜀 |

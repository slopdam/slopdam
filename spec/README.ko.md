# slopdam 명세

[English](README.md) | [한국어](README.ko.md)

이 폴더는 프로그래밍 언어와 상관없이 slopdam의 동작을 정의합니다. 기준 구현은 Python 패키지입니다. 다른 언어(JavaScript, Go, Java, Rust 등)로 옮긴 구현은 `conformance.json`의 모든 사례를 통과하면 올바른 구현입니다.

| 파일 | 내용 | 작성 방법 |
|---|---|---|
| `rules.json` | 프로필, 레벨, 문자 집합, 보호 구역, 순서가 정해진 규칙 목록 | Python 소스에서 생성 |
| `conformance.json` | 입력과, 입력마다 정확한 `reader`와 `dev` 출력 | 입력은 직접 작성, 출력은 생성 |

두 파일 모두 `python scripts/gen_spec.py`로 다시 만듭니다. CI가 `--check`로 실행하므로 명세와 기준 구현이 어긋날 수 없습니다.

## 알고리즘

`clean(text, options)`는 먼저 모든 줄바꿈(`\r\n`, `\r`, `\u2028` 등 Python `str.splitlines`가 아는 것)을 `\n`으로 바꿉니다. 그다음 아래 단계를 한 번의 처리로 실행합니다.

1. 보호 구역을 가립니다. `protected_spans`에 맞는 부분(URL, 인라인 코드, `key=value`의 값, 경로)을 어떤 규칙에도 걸리지 않는 자리 표시자로 바꿉니다.
2. `rules.json`의 순서대로 규칙을 적용합니다. 프로필에 해당 규칙의 동작이 있고, 규칙 레벨이 선택한 레벨 이하이고, 비활성화되지 않았을 때 규칙이 켜집니다. 각 규칙은 앞 규칙이 만든 텍스트에서 맞는 부분을 모두 바꿉니다.
3. 공백이 아닌 문자 뒤에 이어진 공백이나 탭 두 개 이상을 공백 하나로 줄입니다(`tidy.multi_space`). 보호 구역은 아직 가려져 있으므로 그 안의 공백은 그대로입니다.
4. 보호 구역을 되돌립니다. `reader`에서는 인라인 코드 자체가 바뀌지 않는 경우에만 백틱을 뗍니다.
5. 줄을 정리합니다. 비어 있지 않은 첫 줄은 양 끝을, 나머지 줄은 오른쪽 끝을 다듬고, 빈 줄은 버린 뒤 `\n`으로 잇습니다.

흔적 하나를 지우면 다른 흔적이 드러날 수 있습니다(`‒•`에서 대시를 지우면 줄 맨 앞에 글머리 기호가 남습니다). 그래서 한 번의 처리로 텍스트가 바뀌었으면 그 결과로 다시 처리하고, 더 바뀌지 않을 때까지 반복합니다(최대 `tidy.max_passes`번). 따라서 결과는 멱등입니다: `clean(clean(x)) == clean(x)`.

입력에 이미 들어 있는 사용자 정의 영역 문자(U+F0000~U+FFFFD)는 보호 구역으로 다루므로, 구현은 이 범위를 자리 표시자로 써도 됩니다.

## 동작

| `kind` | 의미 |
|---|---|
| `replace` | 맞는 부분을 `value`로 바꿉니다. `\1`은 첫 번째 캡처 그룹입니다. |
| `report` | 텍스트는 그대로 두고, 린터가 수정안 없이 알립니다. |
| `function` | 문맥에 따라 바꿉니다. 아래 표를 보세요. |

| 함수 | 동작 |
|---|---|
| `fullwidth` | 전각 문장 부호를 ASCII로 바꿉니다. |
| `unwrap` | 맞는 부분을 첫 번째 캡처 그룹으로 바꿉니다. |
| `status_tag` | `dev` 전용. 맨 앞의 상태 이모지를 `[OK] `, `[FAIL] `, `[WARN] `으로 바꿉니다. 로그 레벨이 그 태그의 `status_redundant_at` 이상이면 빈 문자열로 바꿉니다. |
| `dash_run` | 이어진 대시의 의미를 앞뒤 문자로 판단합니다. 판단 순서: 옛한글 음절의 일부, 즉 `charsets.hangul_choseong`의 문자 바로 뒤에서 `ᅳ`로 시작하는 경우(유지), 두 글자 이상(구분선: 단어 사이면 공백, 아니면 삭제), 숫자 사이(범위: `reader`는 `~`, `dev`는 `-`), 줄 맨 앞에서 공백이 뒤따름(목록 표시 `- `), 단어 사이(`reader`는 `dash_inline`, `dev`는 ` - `), 그 밖에는 삭제. "단어 사이"란 대시 앞(주변 공백 포함)의 문자가 글자, 숫자, 보호 구역, `dash_word_before` 중 하나이고, 뒤의 문자가 글자, 숫자, 보호 구역, `dash_word_after` 중 하나인 경우입니다. |

## 정규 표현식

패턴은 Python `re` 문법입니다. 다른 엔진에서 주의할 점:

- `\w`, `\d`, `\s`는 유니코드 기준입니다. JavaScript에서는 `u` 플래그와 유니코드 속성 클래스를 쓰세요.
- `\A`는 줄의 시작이 아니라 문자열 전체의 시작입니다.
- `flags: ["multiline"]`이면 `^`와 `$`가 줄 경계에서 맞습니다.
- 뒤쪽 탐색(lookbehind)은 고정 길이입니다.

## 버전

`spec_version`은 규칙이나 사례가 추가될 때가 아니라 파일의 의미가 바뀔 때만 올라갑니다. 각 구현은 자신이 따르는 `spec_version`을 밝히고, 자기 CI에서 `conformance.json`을 실행합니다. 기대 출력이 바뀌면 출력 변경이며 [GOVERNANCE.ko.md](../GOVERNANCE.ko.md)의 정책을 따릅니다.
